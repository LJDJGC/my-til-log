### 💡 学びのポイント
**新規習得：**
- Firestore の更新は `updateDoc`（指定フィールドのみ更新）と `setDoc`（全置換）で意味が違う。セキュリティルールが `userId` を検査する場合、`updateDoc` で `userId` を送らないのが安全
- `idPrefix` のように HTML の `id` を接頭辞化すると、複数フォームが同時に描画されても `label`/`input` の紐付け（アクセシビリティ）が壊れない
- `firebase deploy --only firestore:indexes` は「ファイルに無いインデックス」を検出し、`--force` で削除まで行う（宣言的同期）
- 個人用メモは `.gitignore` に追加してローカル専用にできる（`CONTEXT.md` と同じ扱い）

**理解深化：**
- 追加・編集・削除すべてを「楽観的更新 → 失敗時にスナップショットへロールバック → トースト通知」の同じ型に揃えると、コードの予測可能性が上がる
- テストは純粋関数（ユニット）とUI（コンポーネント）で層を分けると、壊れた箇所を切り分けやすい

**トラブルシューティング：**
- `firebase.json` のキーを `firebase` と誤記 → 正しくは `firestore`。設定ファイルは既存の構造を必ず確認する
- vitest 4 は JSX を oxc が自動変換するため `esbuild.jsx` 設定は不要（`Both esbuild and oxc options were set` の警告が出た）
- テストの `objectContaining` に存在しないキー（`id: undefined`）を書かない

### 🔗 実装コード
- リポジトリ：https://github.com/LJDJGC/routine-tracker
- 主要コード（編集の楽観更新＋ロールバック）：
```ts
const updateSession = (id: string, data: SessionInput) => {
  const previous = sessions;
  const updated = sessions.map((s) => (s.id === id ? { ...s, ...data } : s));
  setSessions(updated);
  localStorage.setItem("sessions", JSON.stringify(updated));

  if (user && db) {
    // userId は変更しないため updateDoc で必要フィールドだけ更新する
    updateDoc(doc(db, "sessions", id), {
      type: data.type,
      duration: data.duration,
      date: data.date,
      note: data.note ?? "",
    }).catch((writeError) => {
      console.error("Firestore 更新失敗:", writeError);
      setSessions(previous);
      localStorage.setItem("sessions", JSON.stringify(previous));
      setError("更新に失敗しました。もう一度お試しください。");
    });
  }
};
```

### 💡 Key Learnings
**Newly Acquired:**
- Firestore updates differ: `updateDoc` (only given fields) vs `setDoc` (full replace). When security rules check `userId`, `updateDoc` is safer because it never sends `userId`
- Prefixing HTML `id`s (e.g. `idPrefix`) keeps `label`/`input` associations intact (accessibility) even when multiple forms render at once
- `firebase deploy --only firestore:indexes` detects indexes missing from the file and deletes them with `--force` (declarative sync)
- Personal notes can be kept local-only by adding them to `.gitignore` (same as `CONTEXT.md`)

**Deeper Understanding:**
- Making add/edit/delete all follow the same "optimistic update → rollback to snapshot on failure → toast" pattern improves predictability
- Splitting tests into pure functions (unit) and UI (component) makes it easier to isolate what broke

**Troubleshooting:**
- Wrote the `firebase.json` key as `firebase` instead of the correct `firestore` — always check the existing config structure
- vitest 4 transforms JSX via oxc, so an `esbuild.jsx` setting is unnecessary (it caused a "Both esbuild and oxc options were set" warning)
- Don't pass non-existent keys (`id: undefined`) to `objectContaining`
