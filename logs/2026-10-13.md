### 💡 学びのポイント
**新規習得：**
- `firestore.rules` は「誰がどのドキュメントを読み書きできるか」を定義する。`request.auth.uid == resource.data.userId` で所有者のみに制限
- `firestore.indexes.json` で複合インデックスを定義すると `where("userId").orderBy("date")` が高速化
- `firebase.json` で `rules` と `indexes` のパスを指定すると `firebase deploy` で一括適用

**理解深化：**
- ルールの `allow create` は `request.resource.data`（書き込み後のデータ）を参照できる。作成時はまだ `resource.data` が存在しないから
- インデックスは `fieldOverrides` でフィールド単位の除外も可能だが、基本は `indexes` 配列で複合指定
- Firebase Console で「インデックス作成中」→「有効」になるまで数分待つ必要あり

**トラブルシューティング：**
- `firestore.indexes.json` で `}` を `]` で閉じるべきところを間違えて `Parse Error` → JSON構造を確認して修正

### 🔗 実装コード
- リポジトリ：https://github.com/LJDJGC/routine-tracker
- 主要コード：
```rules
// firestore.rules
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /sessions/{sessionId} {
      allow read, write: if request.auth != null && request.auth.uid == resource.data.userId;
      allow create: if request.auth != null && request.auth.uid == request.resource.data.userId;
    }
  }
}
```

```json
// firebase.json
{
  "firestore": {
    "rules": "firestore.rules",
    "indexes": "firestore.indexes.json"
  }
}
```
