### 💡 学びのポイント
**新規習得：**
- `let` で変数を宣言し、`=` で値を代入する。宣言と代入は `let message = 'Hello!'` と1行にまとめられるが、可読性のため基本は1行1変数が推奨
- 変数は「名札（ラベル）付きの箱」に例えると分かりやすい。値を書き換えると古い値は消え、別の変数にコピーすると両者が同じ値を持つ
- `const` は再代入できない。`COLOR_ORANGE = '#FF7F00'` のように実行前に決まるハードコード値の別名には、大文字とアンダースコアを使う慣習がある

**理解深化：**
- `var` は古い書き方でほぼ `let` と同じだが、細かな差は「The old "var"」の章で扱う予定。今は `let` / `const` を使うのが基本
- 大文字の定数は「ハードコードされた値の別名」だけに使う。`pageLoadTime` のように実行時に計算される値は、代入後ずっと不変でも小文字のままが自然
- 良い変数名は「中身がひと目で分かる」こと。`data` / `value` のような抽象的すぎる名前や `a`, `b`, `c` は避け、`userName` / `shoppingCart` のように具体的に付ける
- 既存の変数を再利用して「ラベルを変えずに別の物を詰め込む」より、新しい変数を宣言したほうがデバッグが圧倒的に楽。モダンなエンジンでは追加変数による性能問題はほぼ無視できる

**トラブルシューティング：**
- `let message = "This"; let message = "That";` は `SyntaxError: 'message' has already been declared`。同じ変数は1度だけ宣言し、2回目以降は `let` を付けずに代入する
- `let 1a` は数字で始まるので不可、`let my-name` はハイフンが使えないので不可（`-` は減算として解釈される）
- `let let = 5` / `let return = 5` は予約語なので構文エラー。`$` と `_` は普通の記号として使える
- `"use strict"` がない場合だけ `num = 5` のような宣言なし代入が通ってしまう（意図せずグローバル変数が作られる）。strict モードなら `ReferenceError` になる

### 💡 Key Learnings
**Newly Acquired:**
- Declare a variable with `let` and assign a value with `=`. Declaration and assignment can be combined in a single line (`let message = 'Hello!'`), but one variable per line is recommended for readability
- A variable is easy to picture as a "box with a name tag". When the value is replaced the old data is gone, and copying it into another variable leaves both holding the same value
- `const` cannot be reassigned. For hard-coded values known before execution, such as `COLOR_ORANGE = '#FF7F00'`, the convention is to use capital letters and underscores as an alias

**Deeper Understanding:**
- `var` is the old-style keyword and is almost the same as `let`; the subtle differences are covered in the "The old 'var'" chapter. For now, `let` / `const` are the default choice
- Capitalized constants are only for aliases of "hard-coded" values. A value calculated at runtime, like `pageLoadTime`, stays lowercase even though it never changes after assignment
- A good variable name makes its contents obvious at a glance. Avoid overly abstract names such as `data` / `value` and short names like `a`, `b`, `c`; prefer concrete names like `userName` / `shoppingCart`
- It is far easier to debug when you declare a new variable instead of reusing an existing one as a box with the wrong label. Modern engines optimize well enough that extra variables cause almost no performance issues

**Troubleshooting:**
- `let message = "This"; let message = "That";` throws `SyntaxError: 'message' has already been declared`. Declare a variable only once; afterwards assign without `let`
- `let 1a` is invalid because a name cannot start with a digit, and `let my-name` is invalid because hyphens are not allowed (`-` is parsed as subtraction)
- `let let = 5` / `let return = 5` are syntax errors because those words are reserved. `$` and `_`, on the other hand, are ordinary symbols that can be used in names
- Only without `"use strict"` does an assignment without declaration such as `num = 5` succeed (creating a global variable by accident). In strict mode it throws a `ReferenceError`
