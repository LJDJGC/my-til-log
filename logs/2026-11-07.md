### 💡 学びのポイント
**新規習得：**
- `const` は再代入不可、`let` は再代入可能。再代入しない値は `const` を使う
- `const` でもオブジェクトや配列の中身は変更できる（変数自体の再代入が不可なだけ）
- `const` は宣言時の初期化が必須
- `textContent` はDOM標準で高速。CSSの影響を受けず、非表示要素のテキストも含む
- `innerText` は画面に表示されているテキストのみを返し、レイアウト計算（リフロー）が走るため低速
- `getElementById` は対象要素がまだ存在しないと `null` を返す
- `defer` 属性、または `</body>` 直前の配置でDOM構築後にスクリプトを実行できる
- テンプレートリテラル `` `${greeting} ${userName}` `` を使うと文字列結合が読みやすくなる

**理解深化：**
- 教材のコードをそのまま写すのではなく「なぜその書き方なのか」を考えることで理解が深まる
- `textContent` と `innerText` は書き込み時はほぼ同じ結果だが、読み取り時の挙動とパフォーマンスが異なる
- ブラウザでは `name` が `window.name` と名前が被るため、変数名は `userName` などにするのが安全

### 💡 Key Learnings
**Newly Acquired:**
- `const` cannot be reassigned; `let` can. Use `const` for values that do not change
- `const` still allows mutating the contents of objects and arrays (only reassignment of the variable is forbidden)
- `const` requires initialization at declaration
- `textContent` is part of the DOM standard and fast. It is not affected by CSS and includes the text of hidden elements
- `innerText` returns only the text rendered on screen and triggers layout calculation (reflow), making it slower
- `getElementById` returns `null` if the target element does not exist yet
- The `defer` attribute, or placing the script right before `</body>`, runs the script after the DOM is built
- Template literals like `` `${greeting} ${userName}` `` make string concatenation easier to read

**Deeper Understanding:**
- Thinking about "why this style" instead of copying the lesson code deepens understanding
- `textContent` and `innerText` produce almost the same result when writing, but differ in reading behavior and performance
- In browsers, `name` collides with `window.name`, so names like `userName` are safer

**Troubleshooting:**
- None (confirmed that using `const` and `textContent` works correctly)
